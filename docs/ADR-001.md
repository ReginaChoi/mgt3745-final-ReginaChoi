# ADR-001: Keep SkillPath on a hand-built Cloudflare Worker + D1, with the page on GitHub Pages

Status: accepted  
Date: 2026-11-12

## Context
I am continuing SkillPath from HW1 to HW5 (see context/PROJECT.md and context/USERS.md). The target user is an accounting student or recent grad who doesn't know which skills their path needs and has nothing concrete to show an employer (INT-03). The evidence log (F-03) and the export (F-06) already run on a Worker + D1 that I deployed in HW4 (`mgt3745-hw4.rchoi47.workers.dev`).

The forces: the budget is still zero, I'm a first-time coder, and the course grades whether I can inspect and explain what I ship. In HW4 I actually moved data from localStorage to D1, so I know a migration costs real hours. Student evidence text now lives on a server I administer, so I'm the one accountable for it.

## The Gate
- **Build:** keep my own Worker (`worker/src/index.js`) and D1 table (`worker/schema.sql`). I can read every line and I already have it deployed and tested.
- **Buy:** a hosted backend like Supabase or Firebase. It would work, but I'd be trusting their dashboard instead of my own schema, and the export format is theirs.
- **Delegate:** let an AI builder (bolt.new) generate and host the backend. Fastest to something running, but HW5 showed I still had to fix the test script by hand, and I wouldn't know how to get the data out of a builder's hosting.

Delegation still makes sense for individual features (bolt.new did F-06 in HW5, logged in a DDR), but not for where the data lives.

## Options considered
| Option | For | Against |
|---|---|---|
| Build: Worker + D1 (current) | Already deployed; I can read all of it; free tier; `wrangler d1 export` gets data out as SQL | No per-user separation; no offline use; tied to Cloudflare's free-tier terms |
| Buy: Supabase / Firebase | Auth comes built in, which would fix per-user separation | Rebuild against their API; less inspectable; their limits and pricing |
| Delegate: AI builder hosts it | Least work up front | Lowest inspectability; unclear export; HW5 output needed fixes |

## Decision
Build. Keep the Worker + D1 backend from HW4/HW5 and serve the static page (index.html, app.js, styles.css) from the repository root on GitHub Pages. No framework, no runtime npm dependencies. wrangler is the only package, and it's a dev tool.

## Consequences
- Easier: I keep everything I already verified in HW4/HW5 (AC-1 to AC-6, AC-8, F-06 evals), and I can explain every line in a review.
- Harder: everything that touches data depends on Cloudflare (Workers, D1, and wrangler to deploy). If the free tier changes, I have to move both the code and the data. The evidence table is still shared by everyone with the URL, with no per-user separation.
- Harder: moving the page to GitHub Pages means the Worker's CORS origin (still the old Codespace URL) has to change before the deployed page can save anything.
- Sourcing Audit 1 (2026-11-12) checked this decision against dated vendor evidence and didn't change it. It pinned wrangler and removed the unused Gemini/AI Gateway config. Details and exit plans: [docs/SOURCING-AUDIT.md](SOURCING-AUDIT.md).
- Reversal trigger: if Cloudflare changes the Workers or D1 free tier so the project would cost money, or if a second real user needs private evidence (per-user identity), revisit Buy, since a hosted backend with built-in auth would score higher then.
