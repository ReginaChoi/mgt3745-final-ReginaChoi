# ADR-002: Show each visitor only the evidence their own browser saved; keep the shared D1 table

Status: accepted
Date: 2026-11-19
Drafted by Claude Code under [DDR-010](DDR-010.md) at my request; the reversal trigger is the one I set in ADR-001.

## Context
ADR-001's reversal trigger said: "if a second real user needs private evidence (per-user identity), revisit Buy." The Module 12 sessions (docs/FEEDBACK.md) hit it. With three real users, the page showed every row in the table as the visitor's own evidence, including test rows such as `eval-1794972181674` under the audit skills. Sessions 1 and 2 picked the same skill, so session 2 likely opened the page to find session 1's entry already marked "Evidenced", and their own save replaced it on screen. That breaks AC-6 ("WHILE peer comparison is disabled, THE SYSTEM SHALL NOT display any other student's data"), and it made the progress line I asked for in session 2's feedback (S2-3) impossible to count correctly.

## The Gate
Same weights as ADR-001.

| Criterion | Weight | Build: browser remembers its own saves (localStorage), shared D1 unchanged | Buy: hosted backend with auth (Supabase) | Delegate: an AI builder adds login |
|---|---:|---:|---:|---:|
| Cost to start | 4 | 5 (20) | 3 (12) | 3 (12) |
| Cost to maintain | 3 | 5 (15) | 3 (9) | 2 (6) |
| Time to working | 4 | 5 (20) | 2 (8) | 3 (12) |
| Inspectability | 5 | 5 (25) | 2 (10) | 2 (10) |
| Switching cost | 4 | 5 (20) | 2 (8) | 2 (8) |
| Fit to spec | 5 | 3 (15) | 5 (25) | 4 (20) |
| **Weighted total** | | **115** | **72** | **68** |

**Why the losing options lost.** Buy fits the spec best, since real accounts would make evidence private, but it means rebuilding a working backend, adding sign-up friction for users who already took 6 to 12 minutes to save one thing, and three weeks of my time I don't have before Dec 14. Delegate has the same costs plus the HW5 lesson (DDR-001, net -2.55 h).

## Decision
Build. The page stores the saves it made in this browser's localStorage and shows a skill as Evidenced only when that save is still in `GET /entries`. The Worker, the D1 schema and the export from D1 don't change.

## Consequences
- Easier: AC-6 holds on the page again, the progress line counts only the visitor's own saves, and no backend or data change is needed. The guardrail ("0 saves shown as Evidenced that are missing from GET /entries") is now enforced in code and tested (evals/page.test.js).
- **Harder (negative):** evidence is tied to one browser. A student who switches devices or clears site data sees an empty list, even though their rows are still in D1. This is the HW3 problem ADR-001 moved away from, now only for display.
- **Harder (negative):** this is display privacy, not real privacy. `GET /entries` still returns every row to anyone with the URL, so the no-personal-data guardrail and the note by the evidence box still matter just as much.
- Reversal trigger: if any user says they lost their evidence by switching devices or clearing their browser, or if a user wants evidence that others can't read through the API, revisit Buy (auth), since then fit to spec outweighs time to working.
